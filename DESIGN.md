# Flyo support surfaces

Preserve the website's navy (`#061570`), white, Inter / Plus Jakarta Sans typography,
rounded controls and existing package components. Support is an operational
surface: traveller questions and the selected conversation lead; no dashboard
metrics, decorative charts or unrelated redesign.

Use native buttons, inputs, selects, disclosure controls and a native modal
dialog for keyboard focus containment. Support widget styles are isolated in a
shadow root. Keep body text readable, labels explicit and touch targets at least
44px. The launcher sits above the existing WhatsApp/back-to-top controls; mobile
chat uses the available dynamic viewport, with the composer inside the panel.

Motion assessment: the occasional support panel may use opacity plus an 8px
translation at 180ms for spatial continuity, with an 80ms opacity-only reduced
motion variant. Messages, FAQ results and the staff inbox must not animate:
they are frequently read operational data. Availability is a real heartbeat
state, never an ornamental or fabricated online badge.

Administrative spacing uses a 4px base: 8px label/control gaps, 16px related
controls, 20px form rows, and 24px pane gutters (16px on mobile). CMS navigation
is 240px wide; the support inbox list is 360px. Wide data tables scroll within
their container, while form fields stack on mobile. Package editor actions stay
visible while its body scrolls.

Use 400 for body copy, 500 for navigation and labels, and 600 for actions and
section headings. Page headings are 30px in the CMS and 24px in the inbox.
Keep row dates compact, with the full timestamp available on the time element.
All interactive controls have at least 44px height; compact checkboxes retain
their surrounding native label target. Preserve the existing font stack.
